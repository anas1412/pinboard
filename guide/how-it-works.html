How it works ​

Tackora is a Kanban board for coding agents. Every ticket is one agent session: the real CLI (Claude Code or OpenCode 2) running in a terminal inside the ticket. The board shows what each agent is doing, and moves the cards as the work progresses.

This page describes the design. What's built so far is in Status.

The board ​

Tickets are cards in five columns: Open, In progress, Needs review, Changes requested and Resolved. Closed tickets are hidden. The same tickets are also a filterable list, and a journal of what happened each day.

Each card has two pieces of information:

  • Its column: where the work stands.
  • Its agent badge: what the agent is doing right now.
BadgeMeaning
RunningThe agent is working on your last prompt.
DoneThe agent finished its turn and is idle at its prompt. Reply whenever you like.
Needs permissionThe agent is blocked, asking to run a command or edit a file. This is the only state that counts as "needs you".
Not runningNo terminal is open. Opening the ticket resumes the session.

When an agent is Done or Needs permission while Tackora is in the background, you get a desktop notification.

The sidebar's Active list shows every ticket whose agent is working or waiting, with the ones that need you first, so you can jump between agents without going back to the board. Pin any ticket (the pin button next to its title) to keep it under Pinned.

New to Tackora? A Getting started checklist above the board walks you through adding a project, creating and starting a ticket, and trying Ctrl+K. Each step ticks itself off as you do it.

Cards move on their own ​

WhenThe card moves to
You send the agent its first promptIn progress
You submit for review and the pull request opensNeeds review
A reviewer requests changes on the pull requestChanges requested
The agent starts working on those changesIn progress
The pull request is merged, in Tackora or on GitHubResolved (the worktree is removed)
You commit with Finish ticked (direct mode)Resolved

You can always drag a card yourself. Dragging to Needs review submits it for review, and dragging to Resolved merges it (Tackora asks first). Other moves just change the column.

Tickets are sessions ​

Starting a ticket starts its agent session. Tackora chooses the session's ID before the agent starts, so every session is tied to its ticket exactly. Reopening the ticket later, even after restarting Tackora, resumes the same session with its full history.

  • Claude Code starts with claude --session-id <id> and resumes with claude --resume <id>.
  • OpenCode 2 gets its session created through OpenCode's local server with Tackora's ID and the ticket attached, then opens with opencode <folder> --session <id>.

When you start a ticket you choose the model, the effort level (Claude) or model variant (OpenCode), and the permission mode (Claude) or agent (OpenCode). Defaults come from settings. After that, change them inside the agent as usual; the ticket shows what's actually in use. To switch agents, use Start over, which begins a new session and keeps the old one's cost in the ticket's history.

Have a quick question that isn't really a task? Create a quick ticket with just a prompt.

Direct or worktree ​

Each ticket runs in one of two ways. Direct is the default, and each project can set its own default.

Direct (default)Worktree
Where the agent worksThe project folder, on whatever branch is checked out (e.g. main)A separate folder with a new branch for this ticket
Several tickets on one project at onceOne running at a time, so two agents don't edit the same filesYes
When you're doneCommit, optionally push, and tick Finish to resolveSubmit for review opens a pull request. Merging it resolves the ticket.

Worktree branches are named from the ticket, like fix/login-throttle or feat/export-csv. You can edit the name and the base branch when you create the ticket.

Ask Tackora ​

Press Ctrl+K and type what you want in plain words:

  • "Clone anas1412/api and add it as a project"
  • "Add a ticket to web: the signup button does nothing on Safari"
  • "What's waiting for me?"
  • "Move all the docs tickets in api to Closed"

Tackora doesn't have its own AI. It gives your agent (Claude Code or OpenCode) a set of Tackora tools: list and create projects and tickets, edit them, move cards, start sessions. The agent then does what you asked and replies under the command bar, and the cards it changed are highlighted. Press Continue to follow up.

Agents working on tickets get the same tools. In any ticket's terminal you can say "add a follow-up ticket for the signup form", and an agent can file a ticket itself when it spots another problem. Every change records who made it (you, the command bar, or the agent on ticket #7).

Anything destructive or that touches Git waits for you: deleting, removing a project, submitting for review, merging, or changing more than five tickets at once. Tackora shows what's being asked and who's asking, and nothing happens until you click Allow.

Agents ​

When Tackora starts, it looks for claude and opencode on your PATH:

Claude CodeOpenCode
Versionany2.x only. OpenCode 1 counts as not installed.
Signed inrequiredoptional: OpenCode has free built-in models
  • Neither usable: Tackora shows a setup screen with install commands and a Re-check button, and nothing else.
  • One usable: it's used everywhere.
  • Both usable: pick a default in settings and override it per ticket.

Cost and usage ​

Tackora uses what the agents themselves report:

  • Claude Code: hooks say when a prompt starts and when Claude finishes. The status line reports cost, context usage, and your plan's 5-hour and 7-day limits.
  • OpenCode 2: its local server streams events for each session: running, finished, cost and tokens.

Costs add up per ticket, per project and per day on the Usage page.
